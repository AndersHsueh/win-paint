# 签名、分发与公证

> 最后更新:2026-11-15

## 摘要

WinPaint 走 GitHub Releases 外发,不走 App Store。这条路的硬门槛是 **Developer ID Application 证书**:没有它,`.app` 只能 ad-hoc 签名,`spctl` 判 rejected,别人双击会被 Gatekeeper 拦。截至 2026-11-15,本机钥匙串里只有 Apple Development 与 Apple Distribution(Mac App Distribution)两张证书,Developer ID 仍是空的 —— 这是公证的唯一阻塞点。证书申请已经脚本化到只剩「上传一个 .csr 文件」这一步。公证流水线本身已跑通过一次(提交成功、签名链完整、hardened runtime 合格),唯独被证书类型判 Invalid。

## 一、两条路,选哪条

| | GitHub 外发(本项目采用) | Mac App Store 上架 |
|---|---|---|
| 证书 | Developer ID Application | Mac App Distribution(现有那张就是) |
| 公证 | 必须 | **不需要**(App Store Connect 自己会验) |
| 沙盒 | 不需要 | **强制** app-sandbox,需改造文件访问 |
| Profile | 不需要 | 需要 Mac App Store profile |
| 额外要求 | 无 | PrivacyInfo.xcprivacy(隐私清单) |
| 收费 | $99/年开发者账号 | 同左,但走分成 |

选外发的理由:目标用户是「就想改个大小裁个边的人」,不该被迫进 App Store 找;而且 App Store 强制沙盒会把这个「打开本地图片随便改」的核心用途搞复杂(需要 security-scoped bookmark)。

## 二、本机钥匙串实况(2026-11-15)

```
1) 32F4F0151C7C08366D24607371EB7BADBBA9E372 "Apple Development: xue.anders.yh@gmail.com (FHKU84TLG8)"
2) 809B02F28CE4D88C8AEF0F6D57F9B9D25732EFCE "Apple Distribution: Anders Hsueh (BP6XLRFH4K)"
```

第二个虽然显示 "Apple Distribution",实际是 **Mac App Distribution**:

```
subject=UID=BP6XLRFH4K, CN=Apple Distribution: Anders Hsueh (BP6XLRFH4K),
        OU=BP6XLRFH4K, O=Anders Hsueh, C=US
```

### ⚠️ 最大的坑:Xcode 14.3 之后两者同名

| 证书 | EKU OID | 用途 |
|---|---|---|
| Developer ID Application | 1.2.840.113635.100.6.1.4 | 公证、外发 |
| Mac App Distribution | 1.2.840.113635.100.6.1.7 | 只能上 App Store |

在钥匙串里**两者都显示成 "Apple Distribution"**,肉眼看名字完全分不出来。用错的后果:公证提交成功、几分钟后被判 Invalid,日志写:

> The binary is not signed with a valid Developer ID certificate.

所以 `scripts/build-app.sh` 里按 `Developer ID Application` 精确匹配,**绝不按 "Apple Distribution" 猜**。

## 三、申请 Developer ID Application

### 已脚本化的部分

```bash
./scripts/make-developer-id.sh      # 生成 CSR + 私钥(已执行)
./scripts/import-developer-id.sh <下载的.cer>   # 导入钥匙串并绑私钥
```

产物默认落在 `~/Desktop/WinPaint-DID/`:

- `WinPaint-DID.key` — RSA 2048 私钥,权限 600,**故意不进仓库**(仓库是 public GitHub)
- `WinPaint-DID.csr` — 签名请求,subject 已按 Apple 要求填全 CN/OU/O/email/C

OU 用的是团队 ID `BP6XLRFH4K`,与现有 Apple Distribution 证书同队。

### 只能本人做的一步

1. 开 <https://developer.apple.com/account/resources/certificates/list>
2. 「+」→ Certificate Type 选 **Developer ID Application**(别选 Mac App Distribution)
3. 上传 `WinPaint-DID.csr`
4. Download → `DeveloperIDApplication.cer`
5. `./scripts/import-developer-id.sh ~/Downloads/DeveloperIDApplication.cer`

自检:

```bash
security find-identity -v -p codesigning
# 应该多出第 3 条:..."Developer ID Application: Anders Hsueh (BP6XLRFH4K)"
```

### 为什么不直接用钥匙串「证书助理」

「证书助理 → 创建证书」在 GUI 里敲 Apple ID 密码 + 2FA,交互多、易中途失败;而 CSR 这条路里本地步骤完全可脚本化,门户那一步本来就得人来做。多一个脚本换来少一次手动密码输入。

### 导入为什么要用 p12

私钥是 openssl 生成的 PEM,Apple 只发 `.cer` 公钥部分。直接双击 `.cer` 导入,钥匙串里会多一张**没有私钥的证书** —— `codesign` 认不出身份,`find-identity` 也不会列它,等于没装。`import-developer-id.sh` 把「私钥 + 证书 + 中间证书」打包成 p12 再导入,一次性绑好。

### 三个必须知道的坑

**坑 1:Apple 给 Developer ID 的签发方不是 WWDR 那个。**

```
issuer=CN=Developer ID Certification Authority, OU=G2, O=Apple Inc., C=US
```

是 **「Developer ID Certification Authority (G2)」**,专用的中间证书,不是「Apple Worldwide Developer Relations...」。拿错链直接断。证书有效期到 2031-09-17。

**坑 2:`www.apple.com/certificateauthority/` 在墙内 403**(换浏览器 UA 也不行)。但 **Xcode 自带了一份**:

```
/Applications/Xcode.app/Contents/SharedFrameworks/DVTFoundation.framework/Versions/A/Resources/DeveloperIDCA-G2.cer
```

离线就有。脚本按签发方的 CN+OU 精确匹配本地副本,匹配不上才退回 CDN。

**坑 3:OpenSSL 3+ 的 `pkcs12 -export` 默认用 AES-256-CBC + PBKDF2,macOS 钥匙串读不了**,
导入会报:

```
security: SecKeychainItemImport: MAC verification failed during PKCS12 import (wrong password?)
```

看着像密码错了,其实是加密算法不对。必须显式指定老算法:

```bash
openssl pkcs12 -export -inkey key.pem -in leaf.pem -certfile chain.pem \
  -out id.p12 -passout "pass:$PASS" \
  -keypbe PBE-SHA1-3DES -certpbe PBE-SHA1-3DES -macalg sha1
```

### 装好之后的实测签名链

Authority=Apple Root CA

## 四、公证流水线

```bash
./scripts/build-app.sh release        # 签名(--options runtime + --timestamp)
./scripts/notarize.sh AC_PASSWORD     # 提交 → 等验签 → stapling → 验收
```

公证凭据(**app 专用密码**,不是 Apple ID 登录密码)已存在钥匙串,profile 名 `AC_PASSWORD`:

```bash
xcrun notarytool store-credentials AC_PASSWORD \
    --apple-id <你的 Apple ID> --team-id BP6XLRFH4K
```

### macOS 26 上的一个反直觉点

判断凭据存没存,**不要**用:

```bash
security find-generic-password -s notarytool -a AC_PASSWORD   # 查不到
```

这个条目不在 `security` 看得见的经典登录钥匙串里,但 notarytool 走自己的查找路径能正常解密。所以 `notarize.sh` 的前置检查直接问 notarytool:

```bash
xcrun notarytool history --keychain-profile AC_PASSWORD --output-format json
```

能列出提交历史 = 凭据可用。

### 验收标准

```bash
spctl -a -vvv -t exec dist/WinPaint.app     # 期望 accepted
xcrun stapler validate dist/WinPaint.app
```

当前状态:`dist/WinPaint.app` 用 Mac App Distribution 签的,`spctl` = **rejected**(因为那张证书不在 Developer ID Application 授权链上)。签上正确的证书后应转为 accepted。

### 提交件打包

用 `ditto -c -k --keepParent` 而不是 `zip` —— notarytool 收 dmg 之类容易被改坏,ditto 能保住符号链接和扩展属性。

## 五、曾经踩过的坑

1. **`set -euo pipefail` 下 `$(... | grep ...)` 无匹配会静默退出脚本**。`build-app.sh` 里挑证书那行加了 `|| true`。
2. **公证必须 Developer ID Application**,Mac App Distribution 会被拒,见第二节。
3. **App Store 上架路径不需要公证**,也不需要 app 专用密码 —— 那是另一条流水线。
4. **Mac App Store 强制沙盒**。WinPaint 目前无 entitlements(非沙盒),上架需改造。
5. **密钥串里的证书要配私钥 ACL**,否则 codesign 会弹钥匙串授权框,CI 里直接失败。
6. **不要用 `spctl --master-disable`** 关掉安全网,也不要用 `spctl --add`(10.15 起已移除)。
